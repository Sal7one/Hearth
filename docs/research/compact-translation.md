## Local checks

- **QuickMT v2** used the same `Ct2Model` and SentencePiece mode as Hearth. It translated four short inputs covering dialogue, prose and a 3 PM instruction. Three fresh processes took 268–303 ms each, including model loading, after an initial 891 ms run. These timings measure launch and inference together on M4 Pro CPU.
- **Emhotob** used the publisher’s ChatML prompts and greedy decode with PyTorch CPU on the M4 Pro. Median warm time across six bilingual inputs was 14 ms for 5M, 15 ms for 10M and 71 ms for 50M. The 5M version changed milliliters to currency. The 10M and 50M versions also dropped or altered quantities. These small samples can reject a default for live captions, but cannot estimate general accuracy.
- **Jisr INT8** ran the same six inputs in Hearth’s native adapter, using both verified download archives. It retained the recipe’s quantities and units in both directions. It still mangled the English→Arabic time and hallucinated a second time in the reverse direction. The fresh processes took 89–133 ms per input, including load.

For the next comparison, hold the OCR text fixed and measure translation separately. Use the same short dialogue, counters, signs, names and broken OCR lines for the Japanese models. Use English→MSA, English→Saudi and Arabic→English with explicit directions. Record first result, warm p95, repeated and untranslated outputs, and exact retention of numbers, names, units and negation on the same Android phone and Mac. The draft uses the existing catalogue. These candidates have no new download cards.
