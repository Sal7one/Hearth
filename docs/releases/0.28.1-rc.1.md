# Hearth 0.28.1 RC1 · Android CPU/GPU test build

Installable QA candidate for end-to-end device testing. Version **0.28.1 / 95**,
same `com.sal7one.transiber.qa` app ID and verified test certificate as 0.28.0 / 94.
Update the existing QA app to keep its preferences and models. This is an
optimized, minified QA build with test signing; it is not a store release.

Play and FOSS update the same QA app; install one flavor at a time. No model
weights are included. All local TTS and optional GPU plugins require ARM64.

## What changed

- One ABI policy now controls app, common JNI, TTS, ONNX, CMake and archive packaging.
- Fixed ARM64-only library builds retaining x86/ARMv7 prebuilts in their AARs.
- Invalid ABI names and conflicting CLI/IDE selections fail with clear instructions.
- TTS stays one Gradle module and rejects unsupported native builds. ARM64 → x86 →
  ARM64 archive switches were built and checked without cleaning.
- QA package identity and signing were compared with the previous artifacts before
  advancing the version code. No JNI package, pipeline contract or saved model
  configuration changed in this Android build.

## CPU/GPU testing

Use **Benchmark → Compare CPU and GPU backends** with the same model and input.
The detailed matrix is in the validation ZIP. GPU paths are packaged and their
linkage verified; physical Android GPU inference, speed, accuracy and listening
checks remain with the owner. CPU-only engines do not gain GPU support from this
packaging fix. Driver/model failures should remain visible.

## Verification

Both QA flavors/all five APK outputs passed signature, current version/package,
exact native inventory, ELF architecture, page alignment, source/runtime pins,
CPU/GPU dependency isolation and FOSS permission checks. Shared common/speech
host suites, five TTS JNI contract suites, OpenCL loader tests, Android tests,
SDK archive boundary checks and desktop regression suites pass.

The draft remains unpublished pending owner device testing. Builds and checks
were local; no GitHub Actions run was requested or monitored.
