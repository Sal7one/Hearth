# Hearth 0.25.0 draft · Simple setups, more models and optional GPU engines

Hearth keeps its appearance and its independent speech recognition → optional
translation → optional read-aloud pipeline. This update makes everyday setup
smaller, adds portable JSON recipes, expands local models and improves the native
engines. Detailed choices remain available in Advanced mode.

This is a **GitHub draft release**, version code **84**. Its ten APKs are
**unsigned Release builds**, using the base application ID
`com.sal7one.transiber`. They require a maintainer-controlled signing key before
installation. They are not the debug-signed QA builds from earlier releases and
do not update the separate `com.sal7one.transiber.qa` installation. No production
signing identity has been created or substituted for this draft.

## A simpler setup without removing control

- Basic mode presents compact bundles with source/target languages, actual
  download sizes and model readiness. Compact captions uses Whisper Tiny;
  Compact translation combines Whisper Base with a supported direct Marian
  direction; Broad translation combines Nemotron with Index. Availability
  follows each model's real language coverage.
- Advanced mode retains model families, checkpoints, precision variants, custom
  imports, independent GPU choices and utterance-window tuning. Switching modes
  preserves existing choices.
- The model library groups alternate precisions and separates browsing from
  installed/imported models. Language and engine searches replace large option
  walls. The download queue distinguishes transfer, verification, installation,
  failure and repair; transfer percentages do not claim installation is done.
- Translation-only setups omit speech. Read-aloud remains optional and its
  configuration stays independent. A bundle does not silently enable GPU use.

The existing Android TV dashboard, phone interface, colors and settings style
remain. This update also includes the TV branch's text-only subtitle overlay,
compact height controls and separate remote controls. Saved overlay geometry
and Original/Translation/Both preferences retain their meaning.

## Share a setup as JSON

Import a setup, inspect its concrete stages and missing models, then apply it.
Export can include speech, translation and voice independently. Known installed
models are recognized; missing catalog models use the existing pinned download
or import path. Custom models use their family and content digest so that another
device can locate/import the same bytes without relying on an installation ID.

These recipes configure Hearth's existing pipeline. They do not execute arbitrary
nodes or scripts. The shallow schema is versioned, limited to 16 KiB and rejects
unknown fields or unsupported references. API keys, endpoints, model weights,
device paths, source permissions and GPU preferences are excluded. A receiving
device supplies its own connections and local model files. FOSS still requires
offline imports.

Importable examples:

- [English → Arabic captions](https://github.com/Sal7one/Hearth/releases/download/v0.25.0/hearth-en-ar-setup.json)
- [French → English text only](https://github.com/Sal7one/Hearth/releases/download/v0.25.0/hearth-fr-en-text-setup.json)

The text-only recipe leaves speech and voice choices alone. See the
[setup guide](https://github.com/Sal7one/Hearth/blob/v0.25.0/docs/setup-bundles-and-portable-workflows.md) for schema details and
the exact apply behavior.

## Preferences and model locations

User preferences now use DataStore, including appearance, navigation, typed and
conversation translation, camera/reading, voices, connections and the chosen
download location. Migration preserves existing values and encrypted credential
envelopes without changing Keystore encryption. Model indexes, download jobs and
diagnostics remain operational records rather than user preferences. Storage
failures are shown and can be retried.

Imported models remain verified app-private copies for native inference. Hearth
records the selected source document and retains its access permission when the
provider permits it. Each process launch starts an asynchronous audit of local
copies, file metadata and saved source grants, including service and shortcut
entry points. Missing or changed files receive repair controls. This does not
hash an entire multi-gigabyte library or contact document providers on launch:
full pinned/file-tree integrity checks still run before model use, and **Check
source** explicitly opens the original document. Losing the original source does
not invalidate an intact verified private copy.

## More local speech and lightweight translation

The downloadable speech catalog grows from **33 to 49 artifacts**: 15 publisher
speech packages, 27 Whisper variants and seven pinned Vosk packages. This includes
eight added language-specific Moonshine v2 packages and the October 14
**TranscribePsy 250M** release. TranscribePsy supports English, Dutch, French,
German, Italian, Polish, Portuguese and Spanish. Moonshine and TranscribePsy use
bounded utterance windows; continuous microphone input does not make them
cache-aware streaming recognizers. Vosk retains its streaming path.

Marian / OPUS-MT now has **12 direct directions** covering English ↔ Arabic,
Russian, Chinese, French, German and Spanish. Individual packages are roughly
220–242 MiB. Another **30 explicit routes** reuse two direct models through
English, with two inference passes and their associated memory, speed and quality
tradeoffs.

**Index-Translate 2B**, released September 30 with official GGUF weights October
3, adds a 1.22 GiB Q4 multilingual choice with the publisher's 150 language/variety
inventory. Hearth adds its hybrid Qwen3.5 native support, model-specific prompt
and script-aware language routing. Advertised coverage does not establish equal
quality for every language. Model weights remain separate from the APKs; model
licenses and source/integrity details remain visible.

## Native work and optional GPU execution

The C++ translator retains a two-thread CPU worker pool and reuses safe prompt
prefixes where the model architecture permits it. Marian reuses decoder tensor
ownership across tokens instead of copying wrapper-side state repeatedly. Speech
ONNX workers stop spinning while idle. Whisper's automatic-language first call,
streaming context calculation and worker scheduling receive targeted fixes.
These remove identified work; they do not establish an Android speedup by
themselves.

Advanced mode offers independent execution choices:

| Engine | Choices shipped in this draft |
| --- | --- |
| Whisper | CPU; optional ARM64 Vulkan |
| TranscribePsy | CPU; optional ARM64 Vulkan or Adreno OpenCL |
| GGUF translation | CPU; optional ARM64 Vulkan or Adreno OpenCL |
| Other speech engines, Marian, platform translation, TTS and OCR | Their existing independent engines |

CPU remains the default on every supported architecture. Android TVs and other
ARMv7, ARM64, x86 and x86_64 devices retain their CPU paths. The five GPU libraries
are ARM64-only and optional; CPU startup and opening settings do not initialize a
GPU driver. Device features and drivers determine compatibility, rather than a
phone-name allowlist. OpenCL is an optional vendor library, not a mandatory app
requirement.

A selected GPU session reports actual runtime/device information and model-buffer
placement. Unsupported operations can still run on CPU. Missing drivers,
allocation failures and invalid models remain visible errors; they do not become
empty success or an undisclosed CPU fallback. TranscribePsy OpenCL deliberately
keeps TDT decoding on CPU because of an upstream persistent-state issue.

Benchmarks can compare CPU and GPU backends with the same installed model/input
without changing saved preferences. Results separate load, first/warm inference,
actual runtime and output. Speech replay is accelerated input/batch inference;
it does not measure microphone-to-overlay latency.

Real-weight Mac host checks confirmed Index Vulkan model placement and repeated
multilingual inference. Whisper Vulkan matched the tested CPU transcripts after
a GPU flash-attention fix for missing leading words/negation. TranscribePsy CPU
and Vulkan matched all eight language fixtures, but Vulkan was approximately
twice as slow on that host for those short clips. **No Galaxy S25 Ultra, S22 Ultra
or Android TV GPU speedup is claimed.** Phone latency, thermal behavior, memory
pressure and multilingual accuracy remain owner device checks. GPU execution
does not itself improve model quality.

## Draft assets

All APKs below are **unsigned**, release-optimized builds requiring signing before
installation. Play includes optional cloud connections and network downloads;
FOSS has no Internet/network-state permissions and uses local imports. Both
flavors share the base application ID and will replace one another when signed
with the same key. Android 9+ is supported; device-audio capture requires Android
10+. A universal APK contains all four CPU architectures, but does not remove

## Validation and remaining checks

The October 19 integration gate passed the full Gradle tests, both QA Kotlin
compilations, debug native builds and both QA assemblies. Each QA flavor passed
**566 app tests**. Common/speech ASan/UBSan suites, translation wrapper/policy
checks and optional-driver loader checks passed. The QA verifier passed all ten
split/universal APKs, checking native source/binary provenance, exact private
exports, dependency closure, alignment, notices, the optional OpenCL declaration
and FOSS permissions.

Release preparation passed both unsigned Release assemblies and their separate
ten-APK verifier, alongside the required test/native gate and the ten QA APK
checks. The fresh Gradle run completed in 3 minutes 21 seconds (364 tasks).
Git history, staged source and the source-only archive are scanned for secrets
before the draft upload; SHA256SUMS covers every uploaded build/example/archive. No signing
material, provider keys, model weights, research checkouts or generated builds
belong in that source archive. No physical device or paid provider was driven
for these checks. Owner review of the new Basic/Advanced screens, imported setup
flows, upgrades and GPU behavior remains outstanding.
