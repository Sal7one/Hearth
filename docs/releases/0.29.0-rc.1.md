# Hearth 0.29.0 RC1 · Model Lab and settings

Android QA update: **0.29.0 / code 96**, same `com.sal7one.transiber.qa` app
and test certificate as 0.28.1 / code 95. Install over your existing QA app to
keep models and preferences. This is an optimized, minified test build.

Play and FOSS update the same QA app; choose one flavor. All local TTS and
optional GPU plugins require ARM64. No model weights are bundled.

## What changed

- **Settings → Model Lab** is visible in normal mode and directly from quick
  settings. Settings also has localized search and grouped, roomier controls.
  Narrow screens stack paired selectors; saved sheet/back/scroll behavior stays.
- Compare **speech recognition, translation and local TTS voices**. Search the
  pinned catalogue, filter language/family/size/GPU paths, select all matching
  models and confirm a bulk download. There is no 12-model limit: hundreds of
  candidates can be selected, with one engine loaded at a time.
- Comparisons continue across navigation/backgrounding with foreground progress
  and Stop. Android 13+ asks for notifications when needed. If declined, Model
  Lab still shows progress and cancellation. Completed rows survive interruption.
- Advanced controls select 3–10 passes and optionally reuse completed results
  only for exact matching inputs, artifacts, options, app install and backend.
  Per-stage selections and benchmark choices persist in DataStore.
- A searchable, paged comparison table sorts speed, audio throughput, load time,
  first output, reference quality, disk size and recent results. Export the
  filtered comparison as CSV/JSON, or inspect exact output and runtime errors.
  History retains up to 10,000 rows / 64 MiB with atomic per-result writes.
- Requested GPU placement is separate from confirmed execution. Device probes
  and build flags do not prove GPU inference. Whisper Vulkan currently stays
  unconfirmed because its description is a pre-load availability probe.
- TTS measures first PCM and synthesis throughput without playing audio or
  inventing a listening-quality score. Optional battery, thermal and app-memory
  readings are before/after samples, not peak or model RAM.
- Updated Android UI libraries to versions compatible with the existing SDK 36
  build; preserved independent pipeline stages, the single TTS module and ABI
  policy. FOSS remains offline and TVs cannot use local models.

## Testing this candidate

1. On S25/S22, install **Play ARM64** over the previous QA app.
2. Open **Settings → Model Lab → Models → Browse catalogue**. Choose any batch;
   check download/verification progress, leave the page, then return.
3. In Setup choose a repeatable input and languages. Arabic publisher clips work
   immediately; the optional Saudi set uses your own saved recordings.
4. Compare CPU/GPU paths, then inspect **Results**. Filter to the same input and
   look at errors and exact text as well as speed. Try local voice styles with
   the same text; listen to promising voices separately in voice settings.
5. Check navigation, background progress/Stop, saved choices, table exports and
   roomier settings on your phone. No model is declared the phone's winner
   before you measure it.

## Validation and limits

Local Android regression suites and both QA compilations are required, including
real Compose entry-point/500-model-selection tests, large result histories,
backend-evidence checks and foreground-service ownership/cancellation. All ten
QA APKs are verified for current package/version/signing, native inventory and
architecture, ABI isolation, pinned runtime/source integrity, alignment and FOSS
permissions. Validation receipts are grouped in the ZIP.

The benchmark replays/synthesizes input faster than real time; it does not measure
live capture-to-overlay latency. Text reference similarity is not a human quality
judgment. Native crashes and OS process termination can interrupt a comparison.
Physical Android CPU/GPU inference, accuracy, voice listening, notification and
thermal behavior remain owner device tests. Host tests do not establish hundreds
of real model inferences. No adb or GitHub Actions runs were used. This GitHub
draft remains unpublished pending testing.
