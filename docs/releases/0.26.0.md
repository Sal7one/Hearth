# Hearth 0.26.0 · More engines, compact translation and shared voices

This is a **GitHub draft** for owner testing. Galaxy S25 Ultra / S22 Ultra use
`hearth-0.26.0-play-qa-arm64-v8a.apk`. TVs use cloud connections; choose the
universal APK when their CPU is unknown. FOSS remains offline and imports files.

The build is release-optimized, debug-signed **QA**, version **0.26.0 / code 89**,
package `com.sal7one.transiber.qa`. It updates the existing QA installation using
the same signing certificate. Models are separate downloads. No production signing
key, model weights, cloud credentials or remote server are included.

## What changed

| Stage | New integration | Execution |
| --- | --- | --- |
| Speech recognition | Cohere Arabic 07-2026, Fun-ASR MLT Nano, Voxtral Mini Realtime 2602 | Optional ARM64 CPU and Vulkan runtimes |
| Compact translation | QuickMT English→Arabic and Arabic→English as independent packages; SMaLL-100 | Optional ARM64 CTranslate2 CPU runtime with Ruy / SentencePiece |
| GGUF translation | EuroLLM 1.7B Instruct and Riva-Translate 4B v2 prompt protocols | Existing CPU / optional Vulkan / Adreno OpenCL framework |
| Local voices | MagpieTTS v2607 with corrected voice metadata and complete tokenizer | Separate optional ARM64 CPU adapter |
| Shared article TTS | Small model-free core plus Supertonic and Magpie adapters | Reused by Hearth read aloud; no automatic SDK downloads |
| Ming-3.0 | Two TTS bridges, ASR Tiny direct connection, Audio Tiny/Flash transcription bridge | Explicit self-hosted CUDA services; Play only |

STT, optional translation and optional voice output stay independently selectable.
Typed translation, OCR translation and standalone read aloud keep their separate
inputs. Existing engines remain available. The original-captions-while-translating
preference is preserved.

New models stay in Advanced settings rather than becoming unmeasured Basic bundle
defaults. Cards expose pinned sources, complete components and honest execution
requirements. Download completion and model activation remain separate actions.
Imports, restored downloads and portable setup files pass the same integrity and
device-policy checks as visible buttons.

## Translation and speech

QuickMT is directional: downloading en→ar does not install ar→en. The packages are
**363,146,041 B** and **410,561,529 B**. SMaLL-100's selected package is
**344,075,494 B**. These use CTranslate2 rather than launching an LLM decoder for
each subtitle. Actual S25 latency and quality remain to be measured; stored FP16
QuickMT weights compute as FLOAT32 and require more memory than their file size.
[Package, runtime and inference details](../models/ct2-translators.md).

Pinned QuickMT English→Arabic and SMaLL-100 Arabic↔English weights passed sample
inference through Hearth's native host adapter, which caught and corrected QuickMT
tokenization. SMaLL lost a subject in one diacritized Arabic sample; both remain
experimental. QuickMT Arabic→English weights have not run.
[Exact sample outputs and limits](../models/ct2-host-smoke-2026-10-20.md).

The three new speech families use real compiled adapters, pinned model packages,
bounded audio and owned native sessions. Voxtral's current port reprocesses bounded
audio for partials; Hearth does not call this cache-aware streaming. A declared
source language labels downstream translation without pretending to force Voxtral's
recognition language. [Native and real-model evidence](../models/stt-native-expansion.md).
Fun-ASR's pinned production weights received Arabic/English host smoke checks;
Cohere and Voxtral production weights have not run in this workspace.

## Arabic and English voices

The reusable `:hearth-tts` core has no models, network clients, app dependency or
automatic installation. Supertonic supplies verified M1–M5 / F1–F5 voice IDs for
Arabic and English. Its existing broad JNI dependency still needs extraction before
calling that adapter a tiny standalone native distribution.

The new `:hearth-tts-magpie` adapter is separate. Its corrected v2607 generator,
codec and tokenizer download total **678,563,360 B**; installed model assets total
**668,084,575 B**. Bare Arabic maps to the runtime's `ar-MSA` frontend. Speaker IDs
are verified as **Aria, Jason, John, Leo, Sofia**; genders stay unknown until verified.
Family and per-family voice choices persist in DataStore and portable JSON setups.
The SDK keeps bounded PCM, backpressure, cancellation and exclusive native destruction.
[SDK and implementation guide](../handoff/tts-provider-implementation.md).

## Ming-3.0

All five published checkpoints have sourced model cards, immutable revisions,
component sizes and SHA-256 hashes. The 0.5B TTS backbone's complete package is
about **3 GB**; the full Tiny TTS package is about **18 GB**. The audio models' active
parameter counts do not reduce their full stored checkpoint sizes.

These models' published languages **exclude Arabic**. The two TTS bridges expose
five documented English male/female presets, or a user-provided reference voice for
the seven published languages. ASR Tiny uses SGLang-Omni's transcription endpoint.
Audio Tiny/Flash use a bounded bridge around their official ASR chat request, with
the language prefix removed before Hearth's MT stage. Tools and generic audio-chat
responses are not treated as captions. [Setup, sizes and limitations](../ming-3.0.md).

## Validation and owner testing

The required full Gradle tests, both QA Kotlin compilations, common JNI and
Magpie external native Debug builds, and both SDK Release AAR assemblies pass.
Each of the six app variants reports **642 tests, zero failures** (FOSS skips
11 platform/network cases; Play skips two). Shared JNI reports 141 tests per
build type, the core SDK nine, and Magpie three. The core AAR is **39,703 B**;
the optional Magpie AAR is **2,533,736 B**, without model weights.

Common, speech and voice native host suites pass with address/undefined-behavior
sanitizers. The new speech adapter adds 86 sanitized checks. The offline Magpie
JNI fixture verifies exact callback exception identity, UTF-8 errors, malformed
PCM errors, intentional cancellation and stale handles. Python bridge and
package tests, model-card validation and secret scanning also pass.

The final build evidence accompanies the draft assets. Native functionality and
host smoke checks do not establish S25 performance, listening quality or sustained
GPU operation. Owner testing should compare warm latency, memory, heat, Arabic/Gulf
recognition, article pronunciation and stop/restart behavior. No owner device was
driven during implementation.

The remaining prepared targets include Audar, OWSM, Jisr, MOSS Nano, OmniVoice,
native Chatterbox V3 and OuteTTS. Their research cards do not make them installed or
executable models. Ming CUDA inference also remains unexecuted in this workspace.

## Subsequent Riva correction

Real-weight testing for 0.27.0 found that 0.26.0 sent literal backslash-n text in
Riva's role separators, where the pinned publisher Jinja template renders actual
newlines. This could make Riva echo the source instead of translating it. The fix
and real bilingual/cancellation checks are in 0.27.0. The immutable 0.26.0 tag,
source archive and APKs retain the original implementation; this note does not
claim those artifacts were rebuilt.
